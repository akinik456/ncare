
REQUESTER_SCREEN GERÇEK MİMARİSİ

Aslında dosya 5 ana sisteme ayrılıyor:

1. BOOT / INIT SYSTEM

Amaç:
Requester ekranını ayağa kaldırmak.

Akış
initState
↓
_initRequesterId()
↓
_loadGroupId()
↓
_presenceStream hazırlanır
↓
UI canlı hale gelir

İlgili alanlar:

Kritik noktalar:

requesterId
groupId
presenceStream
requesterName

Bu bölüm “ekranın kimliği”.

2. REQUESTER SELF STATE SYSTEM

Bu bölüm requester’ın kendi cihazını yönetiyor.

İçerik
requester location
requester watching durumu
alert preferences
requester timers
Kritik fonksiyon
_getMyLocation()

Bu:

requester GPS okur
distance hesaplarına temel olur
locator card’lara reactive distance sağlar

Şu an yaptığımız notifier optimizasyonu burada 😄

3. LIVE PRESENCE ENGINE (DOSYANIN KALBİ)

Bence dosyanın en kritik sistemi.

Veri kaynakları
Firestore

Kim locator?

groups/{gid}/locators
RTDB

Locator canlı mı?

presence/{locatorId}
Ana akış
Firestore locator docs
+
RTDB presence map
↓
_merge_
↓
presenceForLocator()
↓
LocatorCard

Bunun merkezi:

_presenceForLocator()

Bu fonksiyon:
RTDB raw map → typed UI model çeviriyor.

Aslında mini “mapper layer”.

4. AUTO WAKE SYSTEM

Bu baya profesyonel olmuş brom 😄

Amaç:

Locator sessizleşirse
↓
Requester otomatik RL yollar
↓
Locator BG wake olur
↓
RTDB update gelir

Ana fonksiyon:

_autoWakeStaleLocators()

Çalışma mantığı:

lastSeen > 60sn
↓
90sn cooldown check
↓
_sendRequestToLocator()

Bu sistem aslında:
“presence watchdog”

5. WATCHING SYSTEM

Bence bu da çok önemli.

Requester ekranı açıkken:

Requester watching=true

kapatınca:

watching=false

Locator böylece:

biri onu izliyor mu
fast mode gerekli mi

anlayabiliyor.

Merkez:

_syncWatchingStatus()

ve

_clearWatchingStatus()

Bu aslında requester → locator canlı etkileşim sistemi.

*************
RequesterScreen büyük resim.
flowchart TD
    A[RequesterScreen açılır] --> B[initState]
    B --> C[_initRequesterId]
    C --> D[_loadGroupId]
    D --> E[RTDB presenceStream hazırlanır]

    B --> F[_loadMyName]
    B --> G[_loadAlertSettings]
    B --> H[_getMyLocation timer başlar]

    E --> I[build UI]
    I --> J[Firestore locator listesi]
    J --> K[_filterPairedLocators]
    K --> L[RTDB presence stream]
    L --> M[_parsePresenceMap]
    M --> N[_presenceForLocator]

    N --> O[_LocatorCard render]
    O --> P[Battery / GPS / Accuracy / Distance / Location]

    M --> Q[_autoWakeStaleLocators]
    Q --> R[lastSeen stale mi?]
    R -->|Evet| S[_sendRequestToLocator]
    R -->|Hayır| T[Hiçbir şey yapma]

    K --> U[_syncWatchingStatus]
    U --> V[RTDB watching=true]

    W[dispose] --> X[_clearWatchingStatus]
    X --> Y[RTDB watching=false]
		
Bu chart dosyanın ana omurgası brom: init, streamler, 
locator listesi, presence merge, card render, auto wake ve 
watching cleanup. Bunlar dosyada initState, _loadGroupId, 
_getMyLocation, _autoWakeStaleLocators, _LocatorList, 
_presenceForLocator, _syncWatchingStatus ve 
_clearWatchingStatus etrafında dönüyor.

mantığında 😄

→ typed UI model

çevirisi burada oluyor.
